# فحص شامل للموقع — مجمع باعشن الطبي

**التاريخ:** 2026-08-05  
**البيئة:** فرع `bashen` محليًا على `http://localhost:8080` (`bun --bun run dev`)  
**النطاق:** الموقع العام، مسار الحجز، واجهات API العامة، جودة المحتوى، الفحوصات الآلية، وإشارات من بوابات المصادقة  
**الحكم الإجمالي:** الموقع العام **يعمل ويُحمَّل** على معظم الصفحات، مع **مشكلات حرجة/عالية** تمنع إكمال الحجز وتُظهر بيانات اختبار للجمهور.

## 2. منهجية الفحص

1. تشغيل الخادم المحلي والتحقق من المسارات عبر HTTP.
2. قراءة بيانات Supabase (anon) للفروع/التخصصات/الأطباء.
3. استدعاء `/api/public/book/*` وواجهات أخرى.
4. Lighthouse (desktop) على `/` و `/book` و `/contact` و `/doctors`.
5. `design:contrast` + فحوصات CI المحلية + vitest.
6. لقطات شاشة لصفحات رئيسية (سطح مكتب + موبايل) تحت `/opt/cursor/artifacts/screenshots/`.

> أرقام الأداء من Lighthouse على **وضع التطوير** ليست ممثلة للإنتاج (حزم غير مُصغَّرة، HMR). يُعتمد عليها فقط كإشارات نسبية وأخطاء كونسول.

## 9. خطة إصلاح مقترحة (مرتّبة)

1. **F1** — تصحيح سرّ `SUPABASE_SERVICE_ROLE_KEY` والتحقق من `/api/public/book/availability` يعيد أوقاتًا حقيقية.
2. **F2/F3** — إخراج فرع `e2e-branch` والأطباء DEMO/E2E من `list_public_branches` / قوائم الأطباء العامة (أو `is_active=false`).
3. **F4** — إصلاح أصل الشعار وكسر 404 في الكونسول.
4. **F5/F6** — مواءمة عدّاد خطوات الحجز + عدم إخفاء أخطاء التوفر كـ «لا مواعيد».
5. **F7** — تنظيف بوابات Prettier / portal-tokens على الملفات المتراجعة.
6. إعادة Lighthouse على **production build** (`bun run build && bun run preview`) قبل الاعتماد على أرقام الأداء.

## 10. الحكم النهائي

الموقع العام **جاهز للتصفح والعرض التسويقي** من ناحية التحميل، RTL، SEO الأساسي، والتباين.  
**ليس جاهزًا لاعتبار مسار الحجز «سليمًا للإنتاج»** في هذه البيئة بسبب مفتاح الخدمة غير الصالح وتلوث بيانات الاختبار الظاهرة للزائر.

**التقييم المختصر:** 🟡 صالح للتصفح / 🔴 غير صالح لاعتماد الحجز حتى إصلاح F1–F3.
